# ۲۶ — صفحه پرداخت، جریان زنده، رسید و مینی‌اپ

این سند بخش‌هایی از سرور را توضیح می‌دهد که بدون کلید API کار می‌کنند: صفحه‌ای که خریدار می‌بیند، وضعیتی که خودش را به‌روز می‌کند، رسید امضاشده، و مینی‌اپ تلگرام. هیچ‌کدام برای اتصال اجباری نیستند و همه‌شان روی همان یک دامنه و یک پورت سرو می‌شوند.

## ۱) صفحه پرداخت

| مسیر | چه می‌دهد |
|---|---|
| `GET /pay/{invoice_id}` | صفحه پرداخت فاکتور، همان `payment_url` |
| `GET /pay/{gateway_key}/{invoice_id}` | همان صفحه با مسیر درگاه مشخص |
| `GET /g/{slug}` | درگاه فروشگاه؛ خریدار مبلغ را خودش وارد می‌کند و فاکتور همان‌جا ساخته می‌شود |
| `GET /g/{slug}/{invoice_id}` | صفحه پرداخت فاکتور داخل درگاه فروشگاه |
| `GET /@{slug}` و `GET /@{slug}/{invoice_id}` | همان دو مورد با آدرس کوتاه |

همه این صفحه‌ها HTML می‌دهند و مبلغ و شماره کارت را از دیتابیس می‌خوانند؛ هیچ‌چیز از سمت مرورگر پذیرفته نمی‌شود. آدرس درگاه با آدرس API یکی نیست و تفاوتشان در [سند ۱۵](15-address-map.md) آمده است.

## ۲) وضعیت بدون کلید

`GET /api/v1/public/invoices/{invoice_id}` وضعیت فاکتور را بدون کلید API برمی‌گرداند، برای اپی که فقط `payment_url` را باز می‌کند:

```json
{"success": true, "data": {
  "id": "inv_…", "status": "pending",
  "status_title": "در انتظار واریز",
  "status_hint": "مبلغ دقیق را کارت‌به‌کارت کنید؛ این صفحه به‌صورت خودکار به‌روزرسانی می‌شود.",
  "status_class": "pending",
  "amount_rial": 2500000, "payable_rial": 2500137, "paid_amount_rial": null,
  "store": {"slug": "shop046806", "name": "فروشگاه من"},
  "expires_at": "2026-11-11T09:30:00Z", "paid_at": null,
  "receipt_url": null, "receipt_png_url": null
}, "error": null}
```

وقتی فاکتور `paid` شود، `receipt_url` و `receipt_png_url` هم پر می‌شوند.

| وضعیت | عنوان | معنی |
|---|---|---|
| `pending` | در انتظار واریز | هنوز پولی نرسیده |
| `partially_paid` | پرداخت ناقص | کمتر از مبلغ رسیده، مانده را واریز کند |
| `under_review` | در حال بررسی | واریز ثبت شده و فروشنده بررسی می‌کند |
| `paid` | پرداخت با موفقیت تأیید شد | واریز با پیامک بانک تطبیق خورد |
| `expired` | فاکتور منقضی شده | مهلت تمام شده، فاکتور تازه بساز |
| `cancelled` | فاکتور لغو شده | فروشنده لغو کرده |
| `refunded` | بازگشت وجه | این پرداخت برگشته است |

این مسیر فقط داده نمایشی می‌دهد. برای تصمیم مالی، همان webhook یا `GET /api/v1/invoices/{id}/status` با کلید را مبنا بگذار.

## ۳) جریان زنده با SSE

`GET /api/v1/public/invoices/{invoice_id}/events` یک جریان `text/event-stream` است. هر تغییر وضعیت همان لحظه می‌رسد و در فاصله‌های بی‌تغییر، پیام نگه‌دارنده می‌آید:

```text
data: {"id":"inv_…","status":"pending","payable_rial":2500137,…}

: keep-alive

data: {"id":"inv_…","status":"paid","paid_at":"2026-11-11T09:12:44Z",…}
```

قاعده‌های جریان:

- هر ۱٫۵ ثانیه وضعیت خوانده می‌شود و فقط وقتی عوض شده باشد فرستاده می‌شود.
- بعد از رسیدن به وضعیت پایانی (`paid`، `expired`، `cancelled`، `refunded`) ۳۰ ثانیه باز می‌ماند تا شنونده‌های دیررس هم وضعیت نهایی را ببینند، بعد بسته می‌شود.
- سقف عمر هر اتصال ۱۰ دقیقه است؛ کلاینت باید بعد از آن دوباره وصل شود.
- اگر فاکتور نبود، رویداد `error` با `{"error":"not_found"}` می‌آید.

نمونه در مرورگر:

```javascript
const es = new EventSource(`/api/v1/public/invoices/${id}/events`);
es.onmessage = (e) => {
  const s = JSON.parse(e.data);
  console.log(s.status, s.receipt_url);
  if (["paid", "expired", "cancelled", "refunded"].includes(s.status)) es.close();
};
```

## ۴) رسید

رسید یک توکن امضاشده است و کسی که لینک را دارد می‌تواند ثابت کند پرداخت را سیبیل‌پی تأیید کرده، بدون اینکه به فرستنده لینک اعتماد کند. شماره کامل کارت و شماره تلفن داخل رسید نیست.

| مسیر | خروجی |
|---|---|
| `GET /r/{token}` | صفحه رسید |
| `GET /r/{token}.png` | همان رسید به‌صورت تصویر |
| `GET /api/v1/public/receipts/{token}` | همان رسید به‌صورت JSON |

محتوای رسید: نسخه، شناسه فاکتور، نام و slug فروشگاه، وضعیت، مبلغ سفارش، مبلغ قابل پرداخت، مبلغ وصول‌شده، زمان پرداخت، کد کوتاه فاکتور، چهار رقم آخر کارت، نام بانک، شماره پیگیری بانک، نام سرویس و زمان صدور.

```json
{"v": 1, "invoice_id": "inv_…", "store_name": "فروشگاه من", "store_slug": "shop046806",
 "status": "paid", "amount_rial": 2500000, "payable_rial": 2500137, "paid_amount_rial": 2500137,
 "paid_at": "2026-11-11T09:12:44", "short_code": "4821", "card_last4": "7890",
 "bank": "mellat", "bank_ref": "778899", "issuer": "SIBILPAY", "issued_at": "2026-11-11T09:12:45Z"}
```

اگر توکن دست‌کاری شده باشد پاسخ `404 INVALID_RECEIPT` است. رسید رمزارزی جدا از رسید ریالی است و در [سند ۱۹](19-crypto-payments.md) توضیح داده شده.

## ۵) مینی‌اپ تلگرام

| مسیر | کار |
|---|---|
| `GET /mini` | آدرس ورودی برای BotFather؛ پوسته را سرور می‌سازد |
| `GET /mini/go` | گرفتن `initData` تلگرام، بررسی امضا و برگرداندن پنل آماده |
| `GET /mini/{store_id}/{token}` | لینک امضاشده ربات، بدون نیاز به `initData` |
| `POST /api/v1/mini/me` | همان داده‌ها به‌صورت JSON برای کلاینت API |
| `GET /mini/health` | پاسخ به «چرا مینی‌اپ باز نمی‌شود» |

`GET /mini/health` این چیزها را برمی‌گرداند: https بودن `BASE_URL`، آدرس دقیقی که باید در BotFather ثبت شود، تنظیم بودن توکن ربات (برای بررسی `initData`)، نام کاربری ربات، و سیاست قاب‌بندی صفحه.

```bash
curl -s https://SERVER/mini/health
```

سه چیزی که مینی‌اپ را خراب می‌کند و در همین کد رعایت شده:

- آدرس http؛ تلگرام وب‌اپ http را باز نمی‌کند. آدرس باید https باشد و پورت نداشته باشد، برای همین `MINI_BASE_URL` روی ۴۴۳ است.
- هدر `X-Frame-Options`؛ تلگرام دسکتاپ و وب مینی‌اپ را در iframe نشان می‌دهند و این هدر صفحه را سفید می‌کند. `/mini` این هدر را نمی‌فرستد و `Content-Security-Policy` با `frame-ancestors` تلگرام می‌دهد.
- ورود سمت کلاینت؛ پنل روی سرور رندر می‌شود و اسکریپت صفحه فقط `initData` را به `/mini/go` می‌دهد. `initData` هم طبق قاعده تلگرام با `HMAC_SHA256` بررسی می‌شود و داده کهنه‌تر از ۲۴ ساعت رد می‌شود.

## ۶) چیزهای ثابت روی همان دامنه

| مسیر | کار |
|---|---|
| `GET /downloads/sibilpay.apk` | دانلود اپ اندروید، اگر فایل روی سرور باشد |
| `GET /docs` | مستندات تعاملی، اگر فعال باشد |
| `GET /docs/integration` | راهنمای اتصال سرو شده از همان سرور |
| `GET /health` | سلامت سرویس |
| `GET /api/v1/net/ping` | تست شبکه و پورت |

## ۷) چک‌لیست

- [ ] `payment_url` را از پاسخ API برداشتم، نه دست‌ساز.
- [ ] تصمیم مالی را به webhook یا `status` با کلید گره زدم، نه به این صفحه‌ها.
- [ ] اگر SSE استفاده می‌کنم، بعد از ۱۰ دقیقه دوباره وصل می‌شوم.
- [ ] رسید را با `GET /api/v1/public/receipts/{token}` می‌خوانم و به متن تصویر OCR اتکا نمی‌کنم.
- [ ] `GET /mini/health` سبز است و آدرسی که در BotFather گذاشتم با `entry_url` یکی است.
