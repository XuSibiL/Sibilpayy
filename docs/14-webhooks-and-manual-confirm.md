# ۱۴ — وبهوک و تأیید دستی: از تأیید تا رسیدنِ خبر

> **مسئله‌ای که این سند جواب می‌دهد:** «فاکتور را پرداخت‌شده کردم، ولی سایت/ربات/اپِ
> من خبر نشد.» این سند کلِ زنجیره را می‌گشاید: چه کسی خبر می‌دهد، چه زمانی،
> و از کجا بفهمی کدام حلقه پاره است.

---

## ۱) زنجیرهٔ کامل

```
پیامکِ بانک → اپ/دستگاه → سرورِ سیبیل‌پی → تطبیق (خودکار یا تأیید دستی)
                                   ↓
                          فاکتور «پرداخت‌شده» می‌شود
                                   ↓
        ┌──────────────────────────┼───────────────────────────┐
        ↓                          ↓                           ↓
  پیام به رباتِ فروشنده      وبهوک به آدرسِ شما        پیامِ «اختیاری» به مشتری
  (همیشه)                 (فقط اگر webhook_url ثبت باشد)
```

خبررسانی **سه** جای مستقل دارد و هر کدام می‌تواند جدا از بقیه بترکد:

| گیرنده | شرطِ ارسال | از کجا تنظیم می‌شود |
|---|---|---|
| رباتِ سیبیل‌پی (خودِ فروشنده) | همیشه | — |
| سایت / اپ / رباتِ فروشگاه | فقط اگر `webhook_url` ثبت شده باشد | ربات → «بیشتر» → «🌐 آدرس سایت من» |
| مشتری | فقط اگر فروشنده دکمهٔ پیام را بزند | — |

> **قاعدهٔ اول:** اگر `webhook_url` ثبت نشده باشد، سیبیل‌پی **هیچ** وبهوکی نمی‌فرستد
> — ولی فاکتور پرداخت‌شده **می‌شود**. این دو را از هم جدا بدان.

---

## ۲) قراردادِ وبهوک

```http
POST {webhook_url}
Content-Type: application/json
X-SIBILPAY-Signature: t=1731672600,v1=<hex hmac-sha256>
X-SIBILPAY-Event: invoice.paid
X-SIBILPAY-Delivery: evt_…
```

```json
{
  "event": "invoice.paid",
  "created_at": "2026-11-15T17:42:03+00:00",
  "livemode": true,
  "data": {
    "id": "inv_eke4r4ck4w",
    "status": "paid",
    "amount_rial": 500000,
    "payable_rial": 500838,
    "order_id": "sp-c0dfb0e83fd3bb7262964fd3",
    "short_code": "075055",
    "paid_at": "2026-11-15T17:42:03+00:00",
    "store": {"id": "str…", "slug": "shop046806"},
    "payment_url": "https://SERVER/pay/inv_…"
  }
}
```

**رویدادها:** `invoice.created` · `invoice.paid` · `invoice.partially_paid` ·
`invoice.verified` · `webhook.test`.

### پاسخِ درست

- هر **`2xx`** در کمتر از ۱۰ ثانیه = رسید. بدنه لازم نیست.
- `4xx`/`5xx` = تحویل نشده؛ تلاشِ دوباره با فاصلهٔ ۵ ثانیه، ۱۰، ۲۰ … تا ۱ ساعت.
- **همیشه ۲۰۰ بده و کار را در پس‌زمینه انجام بده.** اگر پردازش سنگین باشد و
  پاسخ دیر شود، سیبیل‌پی آن را ناموفق می‌شمارد و دوباره می‌فرستد.

### امضایی که باید بررسی کنی

```python
# Python
import hashlib, hmac
def verify(secret: str, header: str, body: bytes) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    expected = hmac.new(secret.encode(), body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(parts.get("v1", ""), expected)
```

```php
// PHP
$parts = [];
foreach (explode(',', $_SERVER['HTTP_X_SIBILPAY_SIGNATURE']) as $p) {
    [$k, $v] = explode('=', $p, 2); $parts[$k] = $v;
}
$ok = hash_equals($parts['v1'] ?? '',
      hash_hmac('sha256', file_get_contents('php://input'), $secret));
```

```js
// Node.js
const crypto = require('crypto');
const parts = Object.fromEntries(sig.split(',').map(p => p.split('=')));
const ok = crypto.timingSafeEqual(
  Buffer.from(parts.v1), Buffer.from(
    crypto.createHmac('sha256', secret).update(rawBody).digest('hex')));
```

> امضا را روی **بدنهٔ خام** (`raw body`) حساب کن، نه روی JSONِ پارس‌شده.

## ۳) شش دلیلی که «خبر نرسید»

| نشانه | علت | راهِ درست |
|---|---|---|
| فاکتور پرداخت شد، هیچ درخواستی به سایت نرسید | `webhook_url` ثبت نشده | ربات → «بیشتر» → «🌐 آدرس سایت من» |
| آدرس ثبت است، ولی سرورِ شما هیچ لاگی ندارد | آدرس `http` یا پورتِ اشتباه | `https` و همان پورتی که مسیر را سرو می‌کند |
| `404` در لاگِ سیبیل‌پی | مسیرِ آدرس اشتباه (`/webhook` در برابر `/api/webhook`) | همان مسیری که در سایتِ خودت تست کردی |
| `401`/`500` از سایتِ شما | بررسیِ امضا یا خطای داخلی | اول `200` بده، بعد پردازش کن |
| تکراری می‌آید | پاسخ دیر داده‌ای (>۱۰ ثانیه) | پاسخِ سریع + صف |
| در سایتِ خودت «پرداخت نشد» مانده | وبهوک را دیده‌ای ولی `data.order_id` را نگه نداشته‌ای | با `order_id` سفارش را پیدا و **idempotent** تحویل بده |

## ۴) ابزارِ تشخیص: `/hooks` در ربات

از نسخهٔ **1.5.9.24**، فروشنده در ربات می‌تواند `/hooks` بزند و *واقعیت* را ببیند:

- آدرسِ ثبت‌شده (یا «ثبت نشده»)؛
- آخرین ۸ ارسال با رویداد، وضعیت (`✅ delivered` / `⏳ pending` / `✘ failed`)،
  تعدادِ تلاش، کدِ HTTPِ سایتِ شما و آخرین خطا؛
- دکمهٔ **🔁 ارسالِ دوبارهٔ ناموفق‌ها** و **🧪 ارسالِ آزمایشی**.

پیام‌های «تأیید دستی» و «وصل‌کردنِ واریزی» هم دیگر ادعا نمی‌کنند؛ همان وضعیتِ
دقیق را می‌نویسند («رسید ✅» یا «نرسیده — ۴۰۴»).

## ۵) تأیید خودکار چرا کار نمی‌کرد؟ (موردِ واقعی)

تطبیقِ خودکار فقط وقتی انجام می‌شود که **پیامکِ بانک** به سرور برسد. زنجیرهٔ
سمتِ گوشی این است:

```
اپ → POST {API}/api/v1/device/sms   (با کلیدِ دستگاه)
```

اگر اپ به آدرسِ درست وصل نباشد، هیچ پیامکی نمی‌رسد و «تأیید خودکار» هیچ‌وقت
اتفاق نمی‌افتد — بی‌آنکه خطایی جایی دیده شود. علتِ رایج: اپ با آدرسِ پیش‌فرضِ
زمانِ **build** اجرا شده (`http://10.0.2.2:8000`، آدرسِ شبیه‌ساز).

### قاعدهٔ «دامنه#کد»

از نسخهٔ **1.5.9.24** ربات کدِ اتصال را این‌طور می‌فرستد:

```
pay.mrsibilman.ir#135381
```

اپ این رشته را می‌شکند: آدرسِ سرور از سمتِ چپ، کدِ ۶ رقمی از سمتِ راست.
اگر فقط کدِ خالی را در اپ بزنی، اپ روی آدرسِ پیش‌فرضِ خودش می‌ماند. پس **همیشه
رشتهٔ کامل را پیست کن.**

بعد از اتصال، این را چک کن:

1. ربات → «📱 اتصال اپلیکیشن» → دستگاه باید «🟢 متصل» باشد و «آخرین تماس» تازه.
2. یک واریزِ واقعی بکن → باید در «🔍 نیازمند بررسی» یا مستقیم روی فاکتور بیاید.
3. فاکتور را دستی تأیید کن → `/hooks` باید `invoice.paid` را با `✅ 200` نشان دهد؛
   اگر نداد، همان ردیف می‌گوید چرا.

---

## ۶) چک‌لیستِ انتشار

- [ ] `webhook_url` ثبت و از بیرون `https` است.
- [ ] مسیر را با `curl -X POST` تست کردی و `200` گرفتی.
- [ ] امضا را روی بدنهٔ خام بررسی می‌کنی (`X-SIBILPAY-Signature`).
- [ ] تحویلِ سفارش idempotent است (یک `invoice.paid` تکراری = یک تحویل).
- [ ] پاسخ زیر ۱۰ ثانیه؛ کارِ سنگین در صف.
- [ ] `/hooks` بعد از یک تأیید دستی `✅ 200` نشان می‌دهد.
- [ ] اپ با رشتهٔ `دامنه#کد` وصل شده و «🟢 متصل» است.
