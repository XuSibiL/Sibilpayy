# ۲۳ — راهنمای کامل اتصال

این سند برای برنامه‌نویس فروشگاه نوشته شده: فرستادن فاکتور، گرفتن تأیید، و ساختن ربات. هر مسیر با مثال کارآمد آمده است.

## مفاهیم

| واژه | معنا |
|---|---|
| فروشگاه (store) | کسب‌وکار تو. یک `slug` دارد و یک کیف پول کارمزد. |
| درگاه (gateway) | مسیر پرداخت. `card` یعنی کارت‌به‌کارت با تأیید خودکار پیامک بانک. |
| کلید API | با `sp_live_` یا `sp_test_` شروع می‌شود و فقط یک بار نمایش داده می‌شود. |
| فاکتور (invoice) | یک درخواست پرداخت با مبلغ و عمر محدود (پیش‌فرض ۳۰ دقیقه). |
| مبلغ قابل پرداخت | مبلغ فاکتور به‌علاوه چند ریال، تا هر فاکتور مبلغ یکتا داشته باشد. |
| کارمزد | مبلغ ثابت (نه درصدی) که در لحظه ساخت فاکتور از کیف پول کسر می‌شود. |

## گرفتن کلید

کلید را از ربات تلگرام یا داشبورد وب می‌گیری:

- ربات: «پنل فروشگاه من» «درگاه‌ها و API» دکمه درگاه «کلید و اتصال».
- داشبورد: `/panel/login` «درگاه‌ها» «کلید تازه».

نمونه کلید:

```
sibil_pay_live_a1b2c3_k7x9m2p4q6r8s0t2u4v6w8x0y2
```

این رشته را در هدر بفرست:

```
Authorization: Bearer sibil_pay_live_…
```

کلید `live` برای پرداخت واقعی است و `test` برای آزمایش، بدون تماس با بانک.

## ساختن فاکتور

```bash
curl -X POST https://pay.example.ir/api/v1/invoices \
  -H "Authorization: Bearer sibil_pay_live_…" \
  -H "Content-Type: application/json" \
  -d '{
        "amount_rial": 500000,
        "customer_name": "علی رضایی",
        "customer_phone": "09120000000",
        "order_id": "ORD-1042"
      }'
```

پاسخ:

```json
{
  "success": true,
  "data": {
    "id": "inv_9f2c8b71d4e04a5c9b1f",
    "short_code": "311951",
    "status": "pending",
    "amount_rial": 500000,
    "payable_rial": 500740,
    "pay_url": "https://pay.example.ir/pay/inv_9f2c8b71d4e04a5c9b1f",
    "expires_at": "2026-11-12T05:00:00Z"
  }
}
```

سه نکته موقع فراخوانی:

- `amount_rial` ریال است، نه تومان. ۵۰٬۰۰۰ تومان می‌شود `500000`.
- `payable_rial` ممکن است چند ریال بیشتر باشد. مشتری باید همین عدد را واریز کند؛ همین اختلاف باعث می‌شود واریزش با پرداخت دیگری قاطی نشود.
- در `description` ننویس «پرداخت سفارش»؛ ربات خودش دستور پرداخت را می‌سازد.

خطاهای رایج:

| کد HTTP | `error.code` | معنا |
|---|---|---|
| 401 | `INVALID_TOKEN` | کلید غلط یا باطل شده |
| 402 | `WALLET_INSUFFICIENT` | کیف پول فروشنده برای کارمزد کافی نیست |
| 409 | `NO_CARD_AVAILABLE` | کارت فعالی ثبت نشده |
| 409 | `AMOUNT_POOL_EXHAUSTED` | همه مبالغ یکتای این کارت پر است؛ چند ثانیه بعد تلاش کن |
| 422 | `INVALID_AMOUNT` | مبلغ صفر یا منفی |

## دریافت تأیید پرداخت

بعد از هر پرداخت موفق، SIBILPAY یک `POST` به آدرس webhook فروشگاه می‌فرستد:

```json
{
  "event": "invoice.paid",
  "invoice_id": "inv_9f2c8b71d4e04a5c9b1f",
  "short_code": "311951",
  "amount_rial": 500000,
  "payable_rial": 500740,
  "paid_amount_rial": 500740,
  "paid_at": "2026-11-12T04:43:11Z",
  "order_id": "ORD-1042"
}
```

هدرها:

```
X-SIBILPAY-Signature: sha256=<hex>
```

محاسبه امضا:

```python
import hashlib, hmac
expected = hmac.new(webhook_secret.encode(), raw_body, hashlib.sha256).hexdigest()
assert hmac.compare_digest(expected, header.split("=", 1)[1])
```

بدنه خام را امضا کن، نه دیکشنری پارس‌شده. کلید امضا همان کلید مقصد webhook است (اگر مقصدی ثبت نشده باشد: `webhook_secret` فروشگاه) و هدر `X-SIBILPAY-Signature-Mode` می‌گوید همین درخواست با کدام مسیر امضا شده. نمونه‌های اجراشده در `docs/examples/webhook-verify/` هست.

اگر آدرس تو پاسخ ۲۰۰ ندهد SIBILPAY با فاصله فزاینده تکرار می‌کند و هر تلاش در جدول `webhook_deliveries` ذخیره می‌شود. از داشبورد هم می‌شود دوباره فرستاد.

## کد کارآمد در Python

```python
import requests

BASE = "https://pay.example.ir"
KEY = "sibil_pay_live_…"

def new_invoice(rial: int, order_id: str) -> dict:
    r = requests.post(
        f"{BASE}/api/v1/invoices",
        headers={"Authorization": f"Bearer {KEY}"},
        json={"amount_rial": rial, "order_id": order_id},
        timeout=15,
    )
    r.raise_for_status()
    return r.json()["data"]

def is_paid(invoice_id: str) -> bool:
    r = requests.get(
        f"{BASE}/api/v1/invoices/{invoice_id}",
        headers={"Authorization": f"Bearer {KEY}"},
        timeout=10,
    )
    r.raise_for_status()
    return r.json()["data"]["status"] == "paid"
```

## اتصال به ربات تلگرام

1. در ربات «اتصال اپلیکیشن» «دریافت کد اتصال» را بزن.
2. کد شش‌رقمی را در اپ اندروید SIBILPAY وارد کن.
3. اپ شروع می‌کند به خواندن پیامک‌های بانکی و فرستادنشان به سرور.

از این لحظه هر واریزی که برسد در ربات و در ایمیل گزارش‌ها دیده می‌شود. درگاه بیرونی و API دیگری لازم نیست.

## رفتارهایی که باید رویشان حساب کنی

| موضوع | رفتار |
|---|---|
| عمر فاکتور | ۳۰ دقیقه، بعد از آن `expired` می‌شود و پرداخت دیررس را فروشنده دستی تأیید می‌کند |
| مبلغ اشتباه | اگر مشتری تومان و ریال را جابه‌جا کند تأیید نمی‌شود |
| پرداخت ناقص | وضعیت `partially_paid` و پیام به فروشنده |
| کارمزد | مبلغ ثابت، در لحظه ساخت فاکتور از کیف پول کسر می‌شود و هنگام تأیید پرداخت دوباره گرفته نمی‌شود |
| تکراری | مبلغ یکتا مانع می‌شود دو فاکتور با یک واریز بسته شوند |
| تست | کلید `test` هیچ پول واقعی جابه‌جا نمی‌کند |

## پرسش‌های پرتکرار

چند فروشگاه می‌توانم داشته باشم؟ هر تعداد؛ هر فروشگاه کلید و کیف پول جدا دارد.

کلید لو رفت؟ از همان صفحه «کلید تازه» بگیر؛ کلید قبلی فورا باطل می‌شود.

بدون اپ می‌شود کار کرد؟ برای تأیید خودکار نه؛ اپ همان چیزی است که پیامک بانک را به سرور می‌رساند.

چه ساعتی کار می‌کند؟ ۲۴ ساعته. اگر سرور پایین باشد پیامک‌ها روی گوشی صف می‌شوند و بعد از برگشتن سرور ارسال می‌شوند.

مستندات کجاست؟ همین صفحه: `/docs/integration` روی دامنه خودت.
