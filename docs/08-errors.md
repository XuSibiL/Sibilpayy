# ۰۸ — خطاها و عیب‌یابی

## خواندن خطا

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "INVALID_AMOUNT",
    "message": "مبلغ فاکتور باید بزرگ‌تر از صفر باشد"
  }
}
```

- `code` را در کد خودت بررسی کن؛ ثابت است.
- `message` را می‌توانی به کاربر نشان بدهی چون فارسی و خواناست.
- در خطای اعتبارسنجی، `error.details` هم آرایه‌ای از فیلدهای نامعتبر می‌دهد.

قطعیت خطا مهم است: همه پاسخ‌های `4xx` تضمین می‌کنند فاکتوری ساخته نشده است. اما اگر هیچ پاسخی نرسید، یعنی timeout یا قطع شبکه یا `5xx`، نتیجه نامشخص است و ممکن است فاکتور ساخته شده باشد. در آن حالت با `GET /api/v1/invoices/by-order/{order_id}` تعیین تکلیف کن؛ جزئیات در [سند ۱۰](10-retries-and-idempotency.md).

## خطاهای احراز هویت

| code | HTTP | معنی | راه‌حل |
|---|---|---|---|
| `INVALID_TOKEN` | 401 | کلید نیست یا غلط یا باطل است | هدر `Authorization: Bearer sibil_pay_…` را بررسی کن |

## خطاهای فاکتور

| code | HTTP | معنی | راه‌حل |
|---|---|---|---|
| `INVALID_AMOUNT` | 400 | مبلغ صفر یا منفی یا خیلی بزرگ | `amount_rial` را عدد ریالی درست بده |
| `VALIDATION_ERROR` | 422 | یک فیلد نامعتبر | `error.details` را ببین |
| `INVOICE_NOT_FOUND` | 404 | فاکتور نیست یا مال فروشگاه دیگری است | `id` را بررسی کن |
| `INVOICE_NOT_PAYABLE` | 409 | فاکتور بسته یا منقضی یا لغوشده | فاکتور تازه بساز |
| `INVOICE_ALREADY_VERIFIED` | 409 | قبلا تأیید شده | همان رسید قبلی را استفاده کن |
| `INVALID_TRANSITION` | 409 | تغییر وضعیت غیرمجاز | وضعیت را دوباره بگیر |
| `NO_CARD_AVAILABLE` | 409 | کارت فعالی برای این فروشگاه نیست | در پنل کارت را فعال کن |
| `AMOUNT_POOL_EXHAUSTED` | 409 | مبلغ‌های یکتا تمام شد | فاکتورهای باز را ببند و دوباره تلاش کن |
| `WALLET_INSUFFICIENT` | 402 | کیف کارمزد فروشگاه برای یک فاکتور کافی نیست | فروشنده کیف را شارژ کند؛ پیام همان لحظه در ربات برایش می‌آید |
| `TOPUP_TOO_SMALL` | 400 | شارژ کیف کمتر از حداقل | مبلغ بیشتر |

## خطاهای تنظیمات و درگاه

| code | HTTP | معنی | راه‌حل |
|---|---|---|---|
| `INVALID_WEBHOOK_URL` | 422 | آدرس با `http(s)://` شروع نمی‌شود | آدرس کامل بده |
| `WEBHOOK_NOT_SET` | 409 | webhook ثبت نشده | `PATCH /store` با `webhook_url` |
| `UNKNOWN_GATEWAY` | 404 | چنین مسیر پرداختی نیست | `GET /gateways` |
| `GATEWAY_DISABLED` | 409 | غیرفعال است | `POST /gateways/{key}/enable` |
| `NOTHING_TO_UPDATE` | 400 | بدنه PATCH خالی بود | حداقل یک فیلد بفرست |
| `EVIDENCE_REQUIRED` | 422 | تأیید دستی بدون شناسه یا مبلغ | `sms_id` یا `amount_rial` بده |
| `INVALID_EMAIL` / `EMAIL_TAKEN` | 422/409 | ایمیل نامعتبر یا تکراری | ایمیل دیگر |
| `NOT_FOUND` | 404 | مسیر اشتباه | مسیر را بررسی کن |
| `HTTP_ERROR` / `METHOD_NOT_ALLOWED` | 4xx/4xx | متد یا درخواست نامعتبر | متد درست مثل `GET` یا `POST` |

## عیب‌یابی سناریوهای رایج

### فاکتور ساختم ولی پرداخت نمی‌شود

1. `GET /invoices/{id}/status`؛ اگر `expired` است فاکتور تازه بساز، اعتبار از ۲ تا ۱۸۰ دقیقه است.
2. اگر `pending` است: مشتری دقیقا `payable_rial` را واریز کرده؟ اختلاف چند ریالی مبلغ را تطبیق نمی‌دهد.
3. گوشی تأیید آنلاین و متصل است؟ در `GET /devices` مقدار `last_seen_at` تازه است؟
4. `GET /invoices/{id}/history` را ببین تا بفهمی دقیقا کجا متوقف شده.

### فاکتور `partially_paid` شده

کمتر از مبلغ واریز شده است. یا باقی‌مانده را واریز کن که فاکتور باز می‌ماند، یا لغو کن و فاکتور تازه بساز.

### واریزی آمد ولی به فاکتور نخورد

رویداد `deposit.unmatched` می‌آید و معمولا یعنی مبلغ با هیچ `payable_rial` جور نبوده یا فاکتور منقضی شده بود. با `POST /invoices/{id}/confirm-deposit` دستی وصلش کن.

### webhook نمی‌رسد

- `POST /webhook-test` پاسخ سرور تو را نشان می‌دهد.
- آدرس باید https و عمومی باشد و احراز هویت اضافه نداشته باشد.
- اگر سرورت پشت Cloudflare است، حالت Under Attack را برای این مسیر خاموش کن.

### امضای webhook نمی‌خورد

سه علت رایج:

1. بدنه خام استفاده نشده و JSON دوباره serialize شده.
2. رشته امضا اشتباه است؛ باید `"{t}." + body` باشد نه `body` تنها.
3. کلید امضا اشتباه است یا چرخیده.

### پیام یا سفارش تکراری می‌آید

رویداد دو بار رسیده که طبیعی است. با `order_id` و وضعیت، idempotent شو.

## لاگ و پیگیری

اگر درخواست بد است ولی پاسخ مبهم، این سه را نگه دار و بفرست:

1. زمان دقیق درخواست به UTC
2. `id` فاکتور
3. `code` خطا و `message`

کلید API و شماره کامل کارت را در تیکت نگذار.
