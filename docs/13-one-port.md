# ۱۳ — یک پورت برای API و درگاه

> **قانونِ طلایی:** آدرسی که **API** روی آن است و آدرسی که **صفحهٔ پرداخت** روی آن
> است، باید **یک پورت** داشته باشند. یک میزبان، یک پورت، https.

---

## ۱) چرا؟

هر چیزی که به این سیستم وصل می‌شود — سایت، ربات، اپ، افزونهٔ فروش — فقط **یک**
آدرس می‌شناسد. وقتی این آدرس با آدرسِ صفحهٔ پرداخت یکی نباشد، این‌ها می‌شکنند:

| مشکل | چطور خودش را نشان می‌دهد |
|---|---|
| کوکی/سشنِ صفحهٔ پرداخت | خریدار لینک را باز می‌کند و پیامِ «فاکتور پیدا نشد» می‌بیند |
| ریدایرکتِ https | درخواست از پورتِ A می‌آید و به پورتِ B پرتاب می‌شود؛ ربات پاسخی نمی‌گیرد |
| افزونه‌های آماده | یک `base` هاردکد دارند؛ لینکِ برگشتی روی پورتِ دیگر را معتبر نمی‌دانند |
| وب‌هوک و کال‌بک | آدرسِ ثبت‌شده در درگاه‌های دیگر (کارت، کریپتو) پورتِ قدیمی را دارد |

نتیجهٔ عملیِ این وضعیت، همان پیامی است که در ربات‌های فروش دیده می‌شود:
«**نتیجهٔ ساخت این فاکتور هنوز مشخص نیست**» — یعنی درخواست رفت و پاسخی برنگشت،
و از بیرون هم نمی‌شود فهمید فاکتور ساخته شد یا نه.

---

## ۲) هر لینک از کدام تنظیم ساخته می‌شود

| لینک | تنظیم | پیش‌فرض |
|---|---|---|
| API، سایت، مستندات، APK، ریدایرکت‌ها | `BASE_URL` | — |
| صفحهٔ پرداخت `/{…}/pay/…` و `payment_url` در پاسخِ API | `PAYMENT_BASE_URL` | **همان `BASE_URL`** |
| مینی‌اپ (`/mini`) | `MINI_BASE_URL` | همان میزبان، **بدون پورت (۴۴۳)** |

مینی‌اپ تنها استثناست: تلگرام در URLِ Web App پورت نمی‌پذیرد، برای همین روی ۴۴۳
سرو می‌شود. بقیهٔ لینک‌ها باید یک پورت باشند.

---

## ۳) قانونِ PORT-ONE در کد

از نسخهٔ **1.5.9.22**:

- اگر `PAYMENT_BASE_URL` پورتِ دیگری بدهد، **نادیده گرفته می‌شود** و همهٔ لینک‌ها
  از پورتِ `BASE_URL` ساخته می‌شوند.
- در لاگ یک هشدار ثبت می‌شود:

```
PORT-ONE-V1: پورتِ لینکِ پرداخت (8443) با پورتِ API (2053) یکی نیست؛
             لینک‌ها از پورتِ API ساخته می‌شوند
```

- همین قاعده در ربات هم اعمال می‌شود (`bot/config.py` → `PORT_MISMATCH`)، و
  فرمانِ `/diag` خطِ **«پورتِ درگاه»** را نشان می‌دهد: «یکی ✔» یا «جدا».

اگر واقعاً می‌خواهی عمداً جدا باشند (توصیه نمی‌شود)، در `.env` بگذار:

```
STRICT_ONE_PORT=false
```

---

## ۴) پیکربندیِ درست، در سه خط

```env
BASE_URL=https://pay.example.com
PAYMENT_BASE_URL=https://pay.example.com
MINI_BASE_URL=https://pay.example.com
```

اگر پورتِ صریح می‌گذاری، پورت باید همان پورتی باشد که **مسیرِ `/api/v1/`** را
واقعاً سرو می‌کند — نه پورتی که فقط صفحهٔ پرداخت را می‌شناسد.

`MINI_BASE_URL` عمداً بدونِ پورت است (۴۴۳).

---

## ۵) بررسیِ سریع

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://pay.example.com:2053/health
```

- `200` → همان پورت را هم برای `BASE_URL` و هم `PAYMENT_BASE_URL` بگذار.
- `000` / `502` → سرویس روی آن پورت گوش نمی‌دهد؛ اول nginx/caddy را درست کن،
  بعد آدرس‌ها را عوض کن. **هیچ‌وقت آدرس را قبل از بازکردنِ پورت عوض نکن**، وگرنه
  ربات و سایت با هم می‌خوابند.

از داخلِ سرور می‌توانی مقدارِ نهایی را هم ببینی، نه فقط `.env` را:

```bash
cd /opt/sibilpay && ./venv/bin/python -c "import sys;sys.path.insert(0,'backend');from app.config import settings,payment_base;print(settings.base_url);print(payment_base());print(settings.mini_base)"
```

`BASE_URL` و `PAYMENT_BASE` باید یکی باشند.

## ۶) اگر `302` گرفتی

`302`/`301` با هدرِ `Location` یعنی درخواست **به API نرسیده** و یک لایهٔ دیگر
(وب‌سرور یا پراکسی) آن را به پورتِ دیگر پرتاب کرده است.

```bash
curl -sS -o /dev/null -D - https://pay.example.com/api/v1/invoices/by-order/probe | head -5
```

```
HTTP/2 302
location: https://pay.example.com/api/v1/invoices/by-order/probe   ← یعنی ۴۴۳
server: Caddy
```

مارکِ `server:` منبع را لو می‌دهد:

| `server:` | یعنی پاسخ از کجاست |
|---|---|
| `Caddy` / `nginx` | پراکسی/وب‌سرور ریدایرکت می‌کند؛ کدِ برنامه دخیل نیست |
| `uvicorn` | پاسخ از خودِ برنامهٔ SIBILPAY است |

### دامِ `/health`

`200` روی `/health` **سلامتِ مسیرِ API را ثابت نمی‌کند**. یک پراکسی می‌تواند فقط
`/health` را به برنامه بفرستد و بقیهٔ مسیرها را ریدایرکت کند؛ نتیجه این می‌شود:

```
https://HOST:2053/health          → 200  (uvicorn)
https://HOST:2053/api/v1/…        → 302  (Caddy → 443)
```

یعنی آن پورت «زنده» است ولی **API روی آن نیست**. آدرسِ درست همان پورتی است که
`/api/v1/…` رویش JSON می‌دهد.

### آزمونِ پذیرش

| درخواست | پاسخِ درست | پاسخِ غلط |
|---|---|---|
| `/api/v1/invoices/by-order/probe` بدونِ کلید | `401` + JSON | `302` + `Location` |
| همان مسیر با کلیدِ معتبر و `order_id` ناموجود | `404` + `INVOICE_NOT_FOUND` | `302` یا HTML |
| همان مسیر با کلیدِ معتبر و فاکتورِ موجود | `200` + JSON فاکتور | `302` |

هیچ کلاینتی نباید ریدایرکت را **خودکار دنبال** کند: با فعال‌بودنِ follow، یک
`POST` ممکن است به `GET` تبدیل شود و فاکتور ساخته نشود — در حالی که گزارش می‌گوید
«نتیجه نامشخص».


---

## ۷) چک‌لیست

- [ ] `BASE_URL` و `PAYMENT_BASE_URL` پورتِ یکسان دارند.
- [ ] `https://HOST/api/v1/…` از بیرون JSON می‌دهد (`401` بدونِ کلید) — نه `302`.
- [ ] `https://HOST/health` از بیرون `200` می‌دهد.
- [ ] `MINI_BASE_URL` روی ۴۴۳ است و پورت ندارد.
- [ ] در ربات، `/diag` می‌گوید «پورتِ درگاه: یکی ✔».
- [ ] آدرسِ وب‌هوک/کال‌بکِ درگاه‌های دیگر (کارت، کریپتو) هم به همان پورت اشاره می‌کند.
