# ۰۱ — چرخه یک پرداخت

در دو دقیقه ببین پول و خبر پول از کجا به کجا می‌رود.

## چهار بازیگر

| بازیگر | نقش |
|---|---|
| سایت یا اپ یا ربات فروشنده | فاکتور می‌سازد و منتظر خبر پرداخت شد می‌ماند |
| سرور سیبیل‌پی | صفحه پرداخت، تطبیق واریزی، webhook، امنیت |
| گوشی فروشنده (اپ Forwarder) | پیامک واریز بانک را می‌خواند و به سرور می‌فرستد |
| خریدار | مبلغ را به کارت فروشنده واریز می‌کند |

درگاه بانکی واسطه نیست. پیامک واریز بانک، رسید پرداخت است.

## قدم به قدم

```
خریدار            سایتِ فروشنده            سرورِ سیبیل‌پی            گوشیِ فروشنده
   │                     │                        │                       │
   │  ۱. ثبتِ سفارش      │                        │                       │
   │────────────────────>│                        │                       │
   │                     │ ۲. POST /invoices      │                       │
   │                     │───────────────────────>│                       │
   │                     │<── payment_url ────────│                       │
   │  ۳. بازکردنِ لینک   │                        │                       │
   │<────────────────────│                        │                       │
   │─────────────────────────────────────────────>│  (صفحهٔ پرداخت)       │
   │  ۴. واریزِ مبلغِ دقیق به کارتِ فروشنده       │                       │
   │─────────────────────────────────────────────────────────────────────>│
   │                     │                        │  ۵. پیامکِ بانک       │
   │                     │                        │<──────────────────────│
   │                     │                        │  ۶. تطبیق + تأیید     │
   │                     │ ۷. وب‌هوک invoice.paid │                       │
   │                     │<───────────────────────│                       │
   │  ۸. «پرداخت شد»     │                        │                       │
   │<────────────────────│                        │                       │
```

## گام‌ها با جزئیات

۱) ثبت سفارش. کاربر در سایت تو سفارش می‌دهد و شماره سفارش را نگه می‌داری.

۲) ساخت فاکتور. یک `POST /api/v1/invoices` با مبلغ به ریال و `order_id` خودت. جواب شامل `id` و `payment_url` و `payable_rial` است.

۳) صفحه پرداخت. مشتری `payment_url` را باز می‌کند و مبلغ و شماره کارت و نام صاحب کارت و مبلغ دقیق واریز را می‌بیند.

۴) واریز. مشتری کارت‌به‌کارت می‌کند و باید `payable_rial` را دقیق واریز کند. این عدد مبلغ سفارش به‌علاوه چند ریال یکتاست تا واریزی او با واریزی دیگری قاطی نشود.

۵) پیامک. پیامک واریز روی گوشی فروشنده می‌آید و اپ Forwarder آن را به سرور می‌فرستد؛ فقط پیامک بانکی و از لحظه اتصال دستگاه به بعد.

۶) تطبیق و تأیید. سرور مبلغ و چهار رقم آخر کارت مقصد و بازه زمانی را با فاکتورهای باز مقایسه می‌کند. اگر دقیقا بخورد فاکتور `paid` می‌شود. اگر مبلغ کم یا گرد بود قبول نمی‌شود و به نیازمند بررسی می‌رود.

۷) خبر دادن. سرور یک `POST` امضاشده به آدرس تو می‌زند با `event = "invoice.paid"` و اطلاعات کامل فاکتور. اگر سرور تو جواب ندهد تا ۸ بار با فاصله فزاینده تلاش می‌شود.

۸) بازگشت مشتری. مشتری روی صفحه پرداخت پیام پرداخت شد را می‌بیند و می‌تواند رسید بگیرد و در سایت تو هم وضعیت به‌روز می‌شود.

## وضعیت‌های یک فاکتور

| وضعیت | معنی |
|---|---|
| `pending` | منتظر پرداخت |
| `paid` | پرداخت شد و تأیید شد |
| `partially_paid` | بخشی واریز شده، کمتر از مبلغ |
| `expired` | مهلت تمام شد |
| `cancelled` | خود فروشنده لغو کرد |

## اگر واریزی به هیچ فاکتوری نخورد

پول گم نمی‌شود: واریزی به‌عنوان نیازمند بررسی ثبت می‌شود، فروشنده در تلگرام خبردار می‌شود و می‌تواند دستی به سفارش درست وصلش کند. رویداد `deposit.unmatched` هم برای همین حالت است.
