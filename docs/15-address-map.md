# ۱۵ — کدام آدرس، کجا (درگاه با API فرق دارد)

روی یک دامنه و یک پورت سه آدرس متفاوت زندگی می‌کنند. ظاهرشان شبیه است ولی کارشان کاملا جداست و اشتباه گرفتنشان پرهزینه‌ترین اشتباه نصب است: مشتری به‌جای صفحه پرداخت یک صفحه JSON می‌بیند.

| # | آدرس | شکل | مصرف‌کننده |
|---|---|---|---|
| ۱ | آدرس درگاه فروشگاه | `SERVER/g/<slug>` | مشتری، و فیلد «آدرس درگاه» در فروشگاه‌ساز و وردپرس و ربات یا هر پنل بیرونی |
| ۲ | آدرس پرداخت فاکتور | `SERVER/pay/<invoice_id>` | همان `payment_url` که API در پاسخ ساخت فاکتور می‌دهد؛ خودت نساز |
| ۳ | آدرس API | `SERVER/api/v1` | فقط داخل کد سایت یا ربات یا اپ، با `Authorization: Bearer …` |
| — | پورت | `443` | در آدرس نوشته نمی‌شود و برای درگاه و API یکی است |

نمونه واقعی، فروشگاهی با slug برابر `shop046806`:

```
آدرسِ درگاه   https://pay.mrsibilman.ir/g/shop046806     ← به مشتری / به پنل‌های دیگر
آدرس پرداخت   https://pay.mrsibilman.ir/pay/inv_9f2c…    ← از payment_url
آدرسِ API     https://pay.mrsibilman.ir/api/v1            ← فقط در کد
```

## قاعده اصلی

`/api/v1` هرگز در فیلد «آدرس درگاه» نمی‌نشیند. اگر جایی این فیلد را با `/api/v1` پر کنی، کاربر نهایی صفحه JSON یا `401` می‌بیند نه صفحه پرداخت. آن آدرس فقط برای برنامه‌نویس است.

برعکسش هم غلط است: `…/g/<slug>` را به‌عنوان base آدرس API استفاده نکن، چون هیچ اندپوینتی زیر `/g/` نیست.

## چه کسی چه چیزی می‌خواهد

| طرف | باید چه بگیرد |
|---|---|
| مشتری | فقط `payment_url` یا لینک درگاه عمومی. آدرس API را به او نده. |
| پنل بیرونی مثل فروشگاه‌ساز و وردپرس و ربات دیگر | در فیلد «آدرس درگاه» مقدار `SERVER/g/<slug>` و در فیلد «API» مقدار `SERVER/api/v1` به‌علاوه کلید |
| برنامه‌نویس سایت یا اپ | `SERVER/api/v1` به‌علاوه کلید Bearer؛ فاکتور می‌سازد و `payment_url` را به مشتری می‌دهد |
| سرور خودت برای webhook | فقط آدرس خودت؛ آدرس درگاه و API اینجا نقشی ندارد |

## چطور در ده ثانیه مطمئن شوم درست است

```bash
# ۱) آدرسِ درگاه: باید HTML یا ریدایرکت بدهد، نه JSON
curl -sS -o /dev/null -w "%{http_code} %{content_type}\n" https://SERVER/g/shop046806

# ۲) آدرسِ API بدونِ کلید: باید JSON و 401 بدهد (نه 404)
curl -sS -o /dev/null -w "%{http_code}\n" https://SERVER/api/v1/store

# ۳) آدرسِ API با کلید: باید 200 و همان کلیدهای فروشگاه را بدهد
curl -sS https://SERVER/api/v1/store -H "Authorization: Bearer sibil_pay_live_…"
```

اگر بند ۱ با `application/json` جواب داد یعنی آدرس را با `/api/v1` اشتباه گرفته‌ای.

## داخل ربات و پنل

پیام «درگاه و کلید API» در ربات و صفحه «درگاه‌ها و API» در پنل هر سه آدرس را با برچسب نشان می‌دهند: آدرس درگاه جدا، آدرس پرداخت جدا و آدرس API جدا. چیزی که به بیرون می‌دهی همان آدرس درگاه است، به‌علاوه کلید اگر طرف مقابل با API کار می‌کند.

محدودیت‌ها و کش‌بک و وضعیت webhook در آن صفحه نمایش داده نمی‌شوند؛ جایشان تنظیمات فروشگاه و همین مستندات است.
