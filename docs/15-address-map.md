# ۱۵ — کدام آدرس، کجا؟ (درگاه ≠ API)

روی یک دامنه و **یک پورت** سه آدرسِ متفاوت زندگی می‌کنند. ظاهرشان شبیه است،
کارشان کاملاً جدا. اشتباه‌گرفتنشان پرهزینه‌ترین اشتباهِ نصب است: مشتری به‌جای
صفحهٔ پرداخت، یک صفحهٔ JSON می‌بیند.

| # | آدرس | شکل | مصرف‌کننده |
|---|---|---|---|
| ۱ | **آدرسِ درگاهِ فروشگاه** | `SERVER/g/<slug>` | مشتری؛ و فیلدِ «آدرس درگاه» در فروشگاه‌ساز، وردپرس، ربات یا هر پنلِ بیرونی |
| ۲ | **آدرسِ پرداختِ فاکتور** | `SERVER/pay/<invoice_id>` | همان `payment_url` که API در پاسخِ ساختِ فاکتور می‌دهد — خودت نساز |
| ۳ | **آدرسِ API** | `SERVER/api/v1` | فقط داخلِ کدِ سایت/ربات/اپ (با `Authorization: Bearer …`) |
| — | **پورت** | `443` | در آدرس نوشته نمی‌شود؛ برای درگاه و API یکی است |

نمونهٔ واقعی (فروشگاه با slug = `shop046806`):

```
آدرسِ درگاه   https://pay.mrsibilman.ir/g/shop046806     ← به مشتری / به پنل‌های دیگر
آدرس پرداخت   https://pay.mrsibilman.ir/pay/inv_9f2c…    ← از payment_url
آدرسِ API     https://pay.mrsibilman.ir/api/v1            ← فقط در کد
```

---

## قاعدهٔ طلایی

> **`/api/v1` هرگز در فیلدِ «آدرس درگاه» نمی‌نشیند.**
> اگر جایی این فیلد را با `/api/v1` پر کنی، کاربرِ نهایی صفحهٔ JSON یا `401` می‌بیند،
> نه صفحهٔ پرداخت. آن آدرس فقط برای برنامه‌نویس است.

و برعکسش هم غلط است: `…/g/<slug>` را به‌عنوان Base آدرسِ API استفاده نکن؛
هیچ اندپوینتی زیرِ `/g/` نیست.

---

## چه کسی چه چیزی می‌خواهد؟

| طرف | باید چه بگیرد |
|---|---|
| **مشتری** | فقط `payment_url` (یا لینکِ درگاهِ عمومی). هرگز آدرسِ API را به او نده. |
| **پنلِ بیرونی** (فروشگاه‌ساز، وردپرس، رباتِ دیگر) | در فیلدِ «آدرس درگاه» → `SERVER/g/<slug>`؛ در فیلدِ «API» → `SERVER/api/v1` + کلید |
| **برنامه‌نویسِ سایت/اپ** | `SERVER/api/v1` + کلیدِ Bearer؛ فاکتور می‌سازد و `payment_url` را به مشتری می‌دهد |
| **سرورِ تو (برای وبهوک)** | فقط آدرسِ خودت؛ آدرسِ درگاه/API اینجا نقشی ندارد |

---

## چطور در ده ثانیه مطمئن شوم درست است؟

```bash
# ۱) آدرسِ درگاه: باید HTML یا ریدایرکت بدهد، نه JSON
curl -sS -o /dev/null -w "%{http_code} %{content_type}\n" https://SERVER/g/shop046806

# ۲) آدرسِ API بدونِ کلید: باید JSON و 401 بدهد (نه 404)
curl -sS -o /dev/null -w "%{http_code}\n" https://SERVER/api/v1/store

# ۳) آدرسِ API با کلید: باید 200 و همان کلیدهای فروشگاه را بدهد
curl -sS https://SERVER/api/v1/store -H "Authorization: Bearer sibil_pay_live_…"
```

اگر بند ۱ به `application/json` جواب داد، یعنی آدرس را با `/api/v1` اشتباه گرفته‌ای.

---

## داخلِ ربات و پنل

پیامِ «🔐 درگاه و کلید API» در ربات و صفحهٔ «درگاه‌ها و API» در پنل، هر سه آدرس را
**برچسب‌دار** نشان می‌دهند: «آدرسِ درگاه» جدا، «آدرسِ پرداخت» جدا و «آدرسِ API» جدا.
چیزی که به بیرون می‌دهی، همان «آدرسِ درگاه» است — همراه با کلید، اگر طرف مقابل با
API کار می‌کند.

> محدودیت‌ها، کش‌بک و وضعیتِ وبهوک در همان صفحه نمایش داده نمی‌شوند؛ جایشان
> تنظیماتِ فروشگاه و همین مستندات است.
