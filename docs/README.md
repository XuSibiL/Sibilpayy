# مستندات سیبیل‌پی

هر چیزی که برای وصل کردن روش پرداخت به سایت یا اپ یا ربات تلگرام لازم داری، از صفر تا محیط واقعی.

در همه سندها `SERVER` یعنی آدرس سرور پرداخت، مثلا `https://pay.example.com`. فقط همین یک چیز فرق می‌کند و بقیه مسیرها ثابت است.

یک نکته که خیلی‌ها جابه‌جا می‌گیرند: `/g/<slug>` آدرس درگاه است و `/api/v1` آدرس API. این دو جای هم نمی‌نشینند؛ [سند ۱۵](15-address-map.md) همین را توضیح می‌دهد.

## سه راه برای فهمیدن اینکه پرداخت تأیید شد

| راه | چطور | چه زمانی مناسب است |
|---|---|---|
| webhook | سرور پرداخت خودش به آدرس تو `POST` می‌زند | سایت یا ربات با سرور همیشه روشن |
| پرسیدن وضعیت | هر چند ثانیه `GET .../status` | اسکریپت کوچک بدون سرور عمومی |
| صفحه بازگشت | خریدار بعد از پرداخت به آدرس تو برمی‌گردد | فقط برای تجربه کاربر و مبنای تأیید نیست |

به «کاربر گفت پرداخت کردم» یا به صفحه بازگشت اعتماد نکن. تأیید واقعی یعنی `invoice.paid` در webhook یا `status: "paid"` از API.

## واژه‌نامه

| واژه | معنی |
|---|---|
| فروشگاه (store) | کسب‌وکار تو؛ صاحب کارت و کلید API و کیف پول |
| فاکتور (invoice) | یک سفارش مشخص با مبلغ و اعتبار زمانی |
| `amount_rial` | مبلغ سفارش به ریال، همیشه ریال نه تومان |
| `payable_rial` | مبلغی که مشتری دقیقا باید واریز کند، یعنی مبلغ به‌علاوه چند ریال یکتا |
| `payment_url` | لینک صفحه پرداخت که به مشتری می‌دهی |
| کیف پول کارمزد | کیف پولی که کارمزد هر فاکتور از آن کسر می‌شود |
| دستگاه (device) | گوشی فروشنده که پیامک بانک را می‌خواند |
| webhook | خبر خودکار سامانه به سرور تو |
