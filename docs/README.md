# 📚 مستنداتِ سیبیل‌پی

اینجا همهٔ چیزی است که برای **وصل‌کردنِ روشِ پرداخت** به سایت، اپلیکیشن یا رباتِ
تلگرام لازم داری — از صفر تا محیطِ واقعی.

> **`SERVER`** در همهٔ سندها یعنی آدرسِ سرورِ پرداختِ شما (مثل `https://pay.example.com`).
> فقط همین یک چیز فرق می‌کند؛ بقیهٔ مسیرها ثابت است.

---

> ⚠️ **یک هشدارِ کوتاه قبل از هر چیز:** `/g/<slug>` آدرسِ **درگاه** است و
> `/api/v1` آدرسِ **API**. این دو با هم جابه‌جا نمی‌شوند — [سندِ ۱۵](15-address-map.md).

## سه راه برای فهمیدنِ «پرداخت تأیید شد»

| راه | چطور | کِی مناسب است |
|---|---|---|
| **وب‌هوک** ⭐ | سرورِ پرداخت خودش به آدرسِ شما `POST` می‌زند | سایت/ربات با سرورِ همیشه روشن |
| **پرسیدنِ وضعیت** | هر چند ثانیه `GET .../status` | اسکریپتِ کوچک، بدونِ سرورِ عمومی |
| **صفحهٔ بازگشت** | خریدار بعد از پرداخت به آدرسِ شما برمی‌گردد | فقط برای تجربهٔ کاربر — **مبنای تأیید نیست** |

> ⚠️ هیچ‌وقت به «کاربر گفت پرداخت کردم» یا به صفحهٔ بازگشت اعتماد نکن.
> تأییدِ واقعی = `invoice.paid` در وب‌هوک یا `status: "paid"` از API.

## واژه‌نامهٔ کوتاه

| واژه | معنی |
|---|---|
| **فروشگاه (store)** | کسب‌وکارِ شما؛ صاحبِ کارت، کلیدِ API و کیف پول |
| **فاکتور (invoice)** | یک سفارشِ مشخص با مبلغ و اعتبارِ زمانی |
| **`amount_rial`** | مبلغِ سفارش، به **ریال** (همیشه ریال، نه تومان) |
| **`payable_rial`** | مبلغی که مشتری *دقیقاً* باید واریز کند (مبلغ + چند ریالِ یکتا) |
| **`payment_url`** | لینکِ صفحهٔ پرداخت که به مشتری می‌دهی |
| **کارمزد wallet** | کیف پولِ کارمزد؛ برای هر تراکنشِ موفق کم می‌شود |
| **دستگاه (device)** | گوشیِ فروشنده که پیامک‌های بانک را می‌خواند |
| **وب‌هوک** | خبرِ خودکارِ ما به سرورِ شما |
