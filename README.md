# سیبیل‌پی · SIBILPAY

درگاه پرداخت کارت‌به‌کارت، با تأیید خودکار از روی پیامک بانک.

مشتری مبلغ را کارت‌به‌کارت می‌کند، پیامک واریز بانک روی گوشی فروشنده بررسی می‌شود و سفارش همان لحظه پرداخت‌شده می‌شود. بدون درگاه واسط، بدون دسترسی به حساب، و بدون اینکه منتظر تأیید دستی بمانی.

## این پروژه چیست

سیبیل‌پی برای فروشگاه‌هایی است که کارت‌به‌کارت می‌فروشند و حوصله چک کردن دستی واریزی‌ها را ندارند.

فروشنده کارت خودش را در سیستم ثبت می‌کند. برای هر سفارش فاکتور با مبلغ دقیق یکتا ساخته می‌شود و مشتری همان مبلغ را به کارت فروشنده واریز می‌کند. برنامه اندروید که روی گوشی فروشنده نصب است پیامک بانک را می‌خواند و پرداخت را خودکار تأیید می‌کند.

پول مستقیم به حساب خود فروشنده می‌رود و تأییدش مثل یک درگاه آنلاین خودکار است.

## چطور کار می‌کند

| گام | چه اتفاقی می‌افتد |
|---|---|
| ۱ | فروشنده کارت بانکی خودش را ثبت می‌کند |
| ۲ | سایت یا ربات فروشنده با یک درخواست فاکتور می‌سازد و لینک پرداخت می‌گیرد |
| ۳ | مشتری همان مبلغ را به کارت فروشنده واریز می‌کند |
| ۴ | پیامک واریز روی گوشی فروشنده می‌آید و پرداخت خودکار تأیید می‌شود |
| ۵ | سرور خبر پرداخت شد را با webhook به سایت یا ربات فروشنده می‌فرستد |

## شروع کار

۱. فروشنده در پنل یا ربات مدیریت، فروشگاه می‌سازد و کارت بانکی و کلید API می‌گیرد.

۲. یک فاکتور می‌سازد:

```bash
curl -X POST https://SERVER/api/v1/invoices \
  -H "Authorization: Bearer sibil_pay_live_XXXXXXXX" \
  -H "Content-Type: application/json" \
  -d '{"amount_rial": 2500000, "order_id": "ORDER-1042", "description": "اشتراک ماهانه"}'
```

۳. آدرس webhook را ثبت می‌کند تا خبر تأیید را بگیرد:

```bash
curl -X PATCH https://SERVER/api/v1/store \
  -H "Authorization: Bearer sibil_pay_live_XXXXXXXX" \
  -H "Content-Type: application/json" \
  -d '{"webhook_url": "https://mysite.com/sibilpay/callback"}'
```

۴. مشتری `payment_url` را باز می‌کند، مبلغ دقیق را واریز می‌کند و سایت یا ربات فروشنده با webhook رویداد `invoice.paid` خبردار می‌شود.

جزئیات بیشتر در [شروع سریع](docs/02-quickstart.md) و [webhook](docs/04-webhooks.md) است.

## ویژگی‌ها

- تأیید خودکار پرداخت از روی پیامک بانک، بدون کار دستی
- بدون دسترسی به حساب بانکی: نه رمز اینترنت‌بانک، نه رمز دوم، نه ورود به حساب
- مبلغ دقیق یکتا برای هر فاکتور، تا واریزی‌ها با هم قاطی نشوند
- پشتیبانی از بانک‌های مختلف و تفکیک واریز از برداشت با چند شاهد مستقل
- webhook امضاشده با تلاش مجدد خودکار
- حالت آزمایشی با کلید test، بدون یک ریال پول واقعی
- چند فروشگاه و چند کارت، جدا از هم
- اعلان فوری در تلگرام برای فروشنده و مدیر
- کیف پول کارمزد جدا از پول فروشگاه، تا پول فروش با کارمزد قاطی نشود
- واریزی بی‌صاحب از دست نمی‌رود و برای بررسی می‌ماند

## امنیت و حریم خصوصی

- پول مشتری از حساب فروشنده بیرون نمی‌رود و همان‌جا می‌ماند.
- برنامه به اینترنت‌بانک و رمز دوم دسترسی ندارد و نمی‌خواهد.
- برنامه فقط پیامک‌های بانکی روی گوشی خود فروشنده را می‌خواند تا واریزی را تأیید کند.
- پیامک شخصی، رمز پویا و اطلاعات کارت به سرور فرستاده نمی‌شود.
- هر فروشگاه داده خودش را دارد و گزارش یک فروشگاه در گزارش فروشگاه دیگر نمی‌آید.
- پرداخت مشکوک، یعنی گرد یا بی‌صاحب یا منقضی، خودکار تأیید نمی‌شود.
- درخواست‌های اپ با اثر انگشت امضای خود برنامه بررسی می‌شوند؛ نسخه دست‌کاری‌شده حتی یک درخواست هم نمی‌تواند بفرستد.

بیشتر: [امنیت و ضدتقلب](docs/07-security.md)

## سؤال‌های پرتکرار

پول به حساب کی می‌رود؟ به حساب خود فروشنده. سیبیل‌پی واسطه پول نیست.

به اینترنت‌بانک یا رمز دوم نیاز است؟ نه. هیچ‌جا رمزی وارد نمی‌شود و دسترسی به حساب بانکی داده نمی‌شود.

اگر مشتری مبلغ دیگری واریز کند؟ پرداخت گرد یا بی‌صاحب خودکار تأیید نمی‌شود و برای بررسی و تأیید دستی می‌ماند.

کارمزد چطور حساب می‌شود؟ کارمزد ثابت است و در همان لحظه ساخت فاکتور از کیف پول فروشنده کسر می‌شود، نه از پول فروش. اگر کیف پول برای یک کارمزد کافی نباشد فاکتور ساخته نمی‌شود.

فاکتوری که پرداخت نشود چه می‌شود؟ منقضی می‌شود و کارمزدی که هنگام ساخت کسر شده بود برنمی‌گردد، چون کارمزد بابت صدور فاکتور است.

بیشتر: [سؤال‌های پرتکرار](docs/09-faq.md)
